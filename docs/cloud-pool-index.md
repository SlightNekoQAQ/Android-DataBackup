# Cloud pool recovery index

New writes target `/backup` on each imported personal drive. The app lists the provider root to resolve the actual folder ID or path, and creates the directory if absent. Existing destinations set by older builds are scanned for restore on this device but are not write targets; they are never moved or deleted automatically.

A backup session stores encrypted payloads as `db-<snapshot UUID>-<sequence>.bin`. After all payloads are committed, it writes an encrypted index `db-<snapshot UUID>-databackup-manifest-v1.bin` to each participating drive. Individual replica failures are reported. The index records each original relative path, provider/folder reference, provider file ID, encrypted byte length and SHA-256. It contains no login credentials or signed download URLs. `DBPOOL01` identifies the AES-GCM envelope, whose key is derived from the backup passphrase using PBKDF2-HMAC-SHA256. The recognizable `db-` filenames reveal only snapshot membership/ordering, not original archive names.

On recovery the app lists the configured folders from the authenticated accounts and identifies indexes by filename. After the user unlocks an index, the app resolves references against current personal-drive listings. The file-location view shows original path, drive/account and actual filename when found; missing files/unavailable listings are explicitly marked. Recovery downloads the referenced ciphertext, checks size and SHA-256, and authenticates/decrypts it before exposing it to DataBackup. Copies of an index are not copies of the payloads: other drives may still be required for recovery.
